## Выбор региона и зоны — 07.10.2026, v32

Территории с одинаковыми значениями ПМ на душу населения, для трудоспособных и детей объединены. Для Красноярского края среднее значение по краю не предлагается как территориальный вариант: Красноярск и Канск входят в одну третью зону, северные территории с другими суммами остаются отдельными вариантами. Поиск находит зону по любой входящей в неё территории. Данные всех исходных территорий сохранены; группировка меняет представление выбора.

Регион и зону можно искать вводом, выбирать из прокручиваемого списка или клавишами со стрелками и Enter. Поиск добавлен также для места получения прежнего пособия. Ранее сохранённый город переводится в соответствующую зону; подтверждение поступлений сохраняется только если значения ПМ совпадают.

Проверены 176 модульных тестов и DOM-сценарии поиска, клавиатуры, исторических сумм и восстановления старых черновиков.

## Доработка анкеты — 07.10.2026, v31

При смене ситуации на «Оформляю на детей» или «Я недавно родила» прежний выбор заявления по беременности сбрасывается. Шаги декретных и пособий выделяют незаполненные суммы, даты и получателя; для автоматических сумм требуется проверка поступлений. Обратный порядок месяцев не пропускается без предупреждения. Проверены все модульные тесты и отдельные DOM-сценарии переключения заявления, проверки декретных, восстановления черновика и поправок пособий.

## Текущее состояние

Прототип анкеты и отдельных проверок: расчётный период, уважительные причины отсутствия дохода, состав семьи и исключение супруга по пункту 46, родительские права заявителя по каждому ребёнку, недвижимость и транспорт, источники дохода с выбором галочками, три режима ввода зарплаты, алименты, вклады, единое пособие и демонстрация ступени 50/75/100%. **Нельзя использовать как готовое заключение о праве на пособие**. Калькулятор опубликован на GitHub Pages. Оплата в этом проекте не реализована.

Календарь показывает 12 месяцев компактным списком с раскрываемыми объяснениями. Если для одного заявления на детей есть месяцы без выявленных препятствий по проверенным критериям и рассчитана ступень, отдельно показывается первый месяц с наибольшей предварительной ступенью среди них. Месяцы с неполными данными и несколькими отдельными заявлениями не ранжируются; будущие доходы и решение СФР могут изменить результат.

Для ухода за нетрудоспособным взрослым с даты обращения 21.07.2026 дополнительно спрашивается, относится ли подопечный к предусмотренному кругу членов семьи заявителя. При неизвестном родстве месяцы ухода не засчитываются автоматически, а вывод о минимальном доходе остаётся открытым. Для обращения до изменения прежняя ветка сохраняется. Основание: [поправка к п. 31(л) Правил № 2330](https://www.consultant.ru/document/cons_doc_LAW_532568/25b814292afe61796b2c4954683da33e3b6068c0/) и [разъяснение СФР](https://sfr.gov.ru/branches/orel/news~2026/07/21/283040).

Для автомобиля, недвижимости, другой техники и банковского счёта владелец выбирается отдельно: заявитель, супруг или конкретный ребёнок. При расчёте на дату подачи имущество ребёнка, исключённого из состава семьи, не прибавляется; имущество подопечного не участвует в имущественной проверке. Неизвестный статус ребёнка или удалённая карточка владельца требуют уточнения. Проценты по счетам подопечных проверяются отдельно от самого имущества и исключаются только по предусмотренным для номинального счёта условиям. См. [оценку нуждаемости СФР](https://sfr.gov.ru/grazhdanam/semyam_s_detmi/edinoe_posobie/ocenka/).

Для ребёнка от 18 лет, который включён в состав семьи, индивидуальный минимум дохода проверяется отдельно. Подтверждённые десять месяцев очной учёбы дают исключение; достаточный введённый заработок или стипендия подтверждают минимум. Если учёба короче, доходы неполны или в окно попадает 18-летие с возможным исключением заработка несовершеннолетнего, результат остаётся открытым до проверки иных причин и точных дат. Это не объявляется отказом по умолчанию.

В карточке недвижимости доля всей семьи в объекте по умолчанию явно выставлена 100%; её нужно изменить для долевой собственности. При пустой или некорректной доле проверка имущества остаётся открытой: доли не более одной трети исключаются из подсчёта, и без доли нельзя уверенно назвать превышение по числу объектов или площади. Принадлежность подопечному определяется по выбранному владельцу и его карточке, отдельная противоречивая галочка убрана.

Начальный месяц сравнения устанавливается по местной дате устройства. В режиме постоянной зарплаты месяцы после текущего остаются неизвестными, пока пользователь явно не отметит предположение о сохранении той же суммы в будущем. Это предотвращает автоматическую «гарантию» будущего дохода в 12-месячном прогнозе; введённые помесячно будущие суммы являются прогнозом самого пользователя.

Для зарплаты можно указать одну постоянную сумму и период, разные суммы по месяцам либо общую сумму одного 12-месячного окна. Последний вариант не даёт достоверного прогноза. Пустое поле не трактуется как ноль. Пенсии, пособия, выигрыш и прочие регулярные поступления вводятся по сумме и месяцам; ИП, аренда, продажа имущества, ценные бумаги и авторский доход — по налоговому году. Прожиточный минимум 2026 года подставляется из снимка официальной таблицы СФР от 29.09.2026. В ней 91 субъект и 354 уникальные строки местностей, восемь точных дублей в исходной таблице убраны. Для девяти субъектов с несколькими строками выбор местности обязателен, если значения отличаются. Для 2027 года ПМ пока не подставляется, ступень не выводится. Перед публичным запуском снимок нужно повторно сверить с СФР.

Раз в неделю GitHub Actions сверяет актуальную таблицу СФР с сохранёнными данными. При изменении уже известных сумм или нормативного акта он готовит отдельный запрос на проверку изменений; значения попадут в калькулятор после просмотра и объединения. Изменение структуры таблицы или переход СФР на новый год останавливает задачу с ошибкой, чтобы данные 2027 года не перезаписали 2026-й. Для создания запросов настройка репозитория **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests** должна быть включена. Ручная проверка: `python3 scripts/check_pm.py`; локальная копия страницы: `python3 scripts/check_pm.py --html file.html`.

Добавлены отдельные виды редких доходов по п. 47: возмездная опека, выплата правопреемнику, компенсация за общественные обязанности, медицинский академический отпуск, содержание судьи и пособие при увольнении со службы. Для операций с ценными бумагами требуются и выручка, и расходы; пустые расходы не равны нулю. Это пока не закрывает классификацию всех видов выплат и исключений п. 53.

При выборе «Другие пособия» теперь требуется уточнить вид. Для конкретно указанных в п. 53 выплат (ежемесячная выплата из маткапитала на ребёнка до 3 лет, помощь по социальному контракту, возврат НДФЛ по вычету, социальное пособие на погребение и некоторые виды единовременной материальной помощи) сумма отражается как исключённая. Неопределённый вид оставляет результат открытым; остальные условные исключения не угадываются автоматически.

Материальная помощь работодателя при рождении, усыновлении или установлении опеки проверяется отдельно: выплата в течение первого года, один месяц получения и подтверждённая освобождённая от НДФЛ часть. Только эта часть исключается по п. 53(д); при неизвестной сумме вывод по доходу остаётся открытым.

Заработок в иностранной валюте вводится в исходной валюте с буквенным кодом и курсом ЦБ в рублях за одну единицу на последнее число двенадцатого месяца доходного окна (п. 55). Дата меняется с месяцем подачи, поэтому ранее введённый курс не применяется автоматически к будущим месяцам прогноза. Исторические курсы ЦБ загружаются из официального XML в `data/cbr-rates.json`: для каждого месяца заявления автоматически выбирается своя дата и курс в рублях за одну единицу (номинал 10/100 учитывается). Сохраняются дата запроса и дата действия опубликованного курса — они могут отличаться в выходные. GitHub Actions раз в неделю дополняет новые завершённые месяцы и повторно сверяет последние три; будущие даты не запрашиваются. При отсутствии валюты или даты сохраняется ручной ввод с точной датой, а неизвестный будущий курс оставляет результат открытым. Загрузка: `python3 scripts/check_cbr.py`; первичный снимок содержит даты с января 2024 года по август 2026 года.

По беременности добавлен отдельный предварительный расчёт ступени 50/75/100% от ПМ трудоспособных в первом выбранном месяце, если женщина отметила раннюю постановку на учёт, срок от 12 недель и введены доходы. Для перехода между ступенями учитываются условные восемь месяцев выплаты. В самостоятельной проверке заявления беременной прошлые выплаты на детей, входящих в семью, остаются доходом; при расчёте продления на тех же детей они исключаются. Будущие месяцы, срок фактической выплаты, медицинское подтверждение и порядок одновременного назначения пока не рассчитываются; результат прямо помечен как требующий проверки.

Доходы детей вводятся отдельно с привязкой к ребёнку и месяцу. Зарплата несовершеннолетнего и компенсация за выполнение государственных обязанностей исключаются по пункту 52¹ только при подтверждённом очном обучении не менее шести месяцев в расчётном периоде. Другие доходы ребёнка оцениваются отдельно; неоднозначный месяц 18-летия требует точной даты поступления.

# Изменения в расчёте доходов семьи

Выплачивавшееся единое пособие вводится отдельно с привязкой к ребёнку и месяцам. При общем заявлении на нескольких детей предыдущие выплаты на них исключаются; при отдельных заявлениях пересчитывается каждое заявление. Доходы по алиментам вводятся отдельно от зарплаты. Для новорождённого при действующем назначении на старшего показывается возможность назначения по последнему решению без новой оценки (до шести месяцев со дня рождения). Эти проверки предварительные; источник зарплаты Росстата и сложные варианты алиментов требуют дальнейшей автоматизации.

Пособие по беременности и родам вводится отдельной разовой суммой, месяцем начала начисления и количеством месяцев. Стандартный пример — 5 месяцев, продлённый срок уточняется по документу. За каждый месяц обращения учитывается только доля, попавшая в доходное окно. Минимум 8 МРОТ теперь сравнивается с указанным подходящим доходом отдельно для заявителя и супруга; это не заменяет остальные обязательные проверки.

Семейное положение заявителя выбирается отдельно от наличия второго родителя у ребёнка. Статус «никогда не состояла в браке» и повторный брак не запускают условный минимум алиментов; фактически поступившие деньги по ним по-прежнему вводятся. Для разведённого отдельно различаются суд, приказ, ФССП, нотариальное соглашение и неоформленные алименты. Нотариальная сумма берётся из соглашения, даже если фактически перечисляли меньше.

Для расчётного минимума алиментов нужны окончательные годовые суммы Росстата и месяцы их официальной публикации. Значение за предыдущий год начинает действовать только со следующего месяца после публикации; до этого берётся год перед ним. Календарь пересчитывает применимый год для каждого месяца обращения. Подтверждённые записи из еженедельной сверки подставляются автоматически, остальные можно указать вручную с проверкой специалистом.

Еженедельная задача `.github/workflows/check-rosstat.yml` по средам сверяет официальную годовую таблицу Росстата и предлагает изменения в `data/rosstat-wages.json` отдельным pull request. Она ищет новый год, в том числе 2026-й в 2027 году, с первой недели года: если данные появятся в марте, ближайшая недельная проверка их обнаружит. Предварительные показатели сохраняются с пометкой, но **не становятся применимыми**. Для каждого нового или изменённого года остаются `final_confirmed: false` и `publication_month: null`: необходимо подтвердить окончательность и фактический месяц официального опубликования. После проверки и объединения записи с подтверждёнными данными автоматически подставляются в анкету по региону и году; неизвестные субъекты и годы остаются открытыми. До первого подтверждённого импорта доступен ручной ввод.

### Прогноз на 2027 год и анкета

Если официальные ПМ или МРОТ на 2027 год не загружены, доступен отдельный сценарий: по умолчанию суммы 2026 года без роста, с отдельно редактируемым процентом изменения ПМ и МРОТ. Официальные загруженные значения имеют приоритет. Используемые допущения и правила оценки 2026 года перечислены в каждом прогнозном месяце; такой сценарий не участвует в выборе лучшего месяца по официальным данным. Неизвестные доходы по-прежнему не заменяются нулями.

Имущество выбирается по видам, начиная с квартиры. Снятие отметки исключает объект из текущего расчёта, сохраняя заполненные поля в черновике. Старые пособия доступны в категории доплат за прошлые периоды. Получатель для назначения новорождённому определяется по явно заполненным карточкам старших детей.

## v33 — территориальные группы ПМ
Официальные названия вместо универсальной «зоны»; состав и источник раскрываются у каждого варианта. Убраны общеобластные агрегаты Коми, Якутии, Красноярского края, Архангельской, Иркутской и Томской областей из территориального выбора. Добавлены населённые пункты подгруппы 2 Таймыра, исключения Мирнинского и Приморского районов. Значения ПМ сохранены по официальной таблице СФР за соответствующий год.

## v34 — сверка Коми, Амурской и Архангельской областей
Архангельская зона II исправлена после чтения текста приложения. Уточнены состав зон Коми с подчинёнными территориями, отдельная амурская величина по перечню № 1946 и исключение Муртыгита. Состав Архангельской области за 2026 год больше не дублирует старые районы и новые округа. Источники и ограничения проверки записаны в `territorial-pm-review.md`.

## v35 — выбор доходов и прогноз поступлений
Все виды дохода видны без раскрытия списка. Сначала пользователь отмечает виды, затем отдельными шагами указывает суммы и периоды только выбранных доходов. Отметки о будущей зарплате и пособиях сопровождаются объяснением: это ожидаемые поступления для примерного сравнения следующих месяцев подачи, а не изменение фактически полученных доходов.

## v36 — БиР и переходы к недостающим ответам
Выбор БиР подписан полным названием, инструкция видна без раскрытия подсказки. Сравнение прежних выплат вынесено в необязательный раздел условий; новое заполнение предполагает отсутствие такого перехода, пользователь может изменить ответ, прежний явный ответ из черновика сохраняется. Правило сравнения сумм не изменено. Для каждого месяца расчёта показаны конкретные недостающие доходы и периоды, с кнопкой к полю и возвратом к пересчитанному результату. Помесячная зарплата открывается на нужном месяце нужного взрослого.

## v37 — месяц поступления единого пособия
Автоподстановка использует размер за предыдущий месяц начисления: январское поступление — декабрь предыдущего года, февральское — январь текущего. Доход остаётся в месяце фактического поступления. Ручные исправления для досрочных, двойных, пропущенных выплат и первого назначения сохраняются. Старые подтверждения автоматических сумм требуют повторной проверки после изменения правила. Январь 2027 использует известную сумму за декабрь 2026, февраль 2027 без официальных данных не получает выдуманной суммы. Основание: [график СФР](https://sfr.gov.ru/press_center/news/~2025/01/28/269704), [пояснение СФР за 2026 год](https://sfr.gov.ru/branches/altaikr/news/~2026/01/21/278242).
